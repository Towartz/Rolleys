# Rolleys Foreign Function Interface (FFI) Guide

Rolleys provides first-class foreign function interfaces to enable integration into non-Rust ecosystems:
- **C-ABI (`baileys-cabi`)**: Native C headers for C, C++, C#, Flutter / Dart, Python `ctypes`, and Go `cgo`. Events are delivered through `baileys_client_set_event_callback` as JSON.
- **UniFFI (`baileys-ffi`)**: High-level idiomatic bindings generating Kotlin for Android (JNI) and Swift for Apple platforms (iOS, macOS).
- **Node-API (`baileys-napi`)**: Native addon for Node.js, Bun, and Electron.

---

## 1. C-ABI Integration (`baileys-cabi`)

Headers are located at [`bindings/c/baileys.h`](../bindings/c/baileys.h).

### Building Dynamic / Static Libraries
```bash
# Build release shared library (DLL / SO / DyLib)
cargo build --release -p baileys-cabi
```
Outputs:
- Windows: `target/release/baileys_cabi.dll` & `baileys_cabi.lib`
- Linux / Android: `target/release/libbaileys_cabi.so`
- macOS: `target/release/libbaileys_cabi.dylib`

### Conventions
- Functions return `0` on success, `-1` for an invalid argument or handle, `-2` when the operation failed. Functions returning `char*` return `NULL` on failure; free every returned string with `baileys_free_string`. Structured results are JSON.
- After a failure call `baileys_last_error()` for the reason (thread-local, reset by each generated function on entry). Optional numbers are `int64_t` with a negative value meaning "not set".
- `bindings/baileys-cabi/src/parity.rs` and the matching part of `baileys.h` are generated by `scripts/gen-cabi-parity.py`; edit its table, not the output. CI fails if they drift.

### Example C Integration
```c
#include "baileys.h"
#include <stdio.h>

/* Runs on a runtime worker thread; event_json is only valid during the call. */
void on_event(const char* event_json, void* user_data) {
    (void)user_data;
    printf("[event] %s\n", event_json);
}

int main(void) {
    BaileysClientHandle* client = baileys_client_create_sqlite("session.db");
    if (!client) {
        fprintf(stderr, "could not open session.db\n");
        return 1;
    }

    /* Register before connecting to see the QR code and connection events. */
    baileys_client_set_event_callback(client, on_event, NULL);

    if (baileys_client_connect(client) != 0) {
        fprintf(stderr, "connect failed\n");
        baileys_client_destroy(client);
        return 1;
    }

    char* id = baileys_client_send_text(client, "1234567890@s.whatsapp.net", "Hello from C!");
    if (id) {
        printf("sent %s\n", id);
        baileys_free_string(id);   /* strings returned by the library must be freed with this */
    }

    getchar();   /* keep the process alive while events arrive */

    baileys_client_destroy(client);
    return 0;
}
```

## 2. Android Kotlin / JNI (`baileys-ffi`)

Rolleys uses Mozilla's `uniffi-rs` to generate thread-safe JNI bridges without manual JNI C boilerplate.

### Target Architecture Matrix
- `arm64-v8a` (`aarch64-linux-android`)
- `armeabi-v7a` (`armv7-linux-androideabi`)
- `x86_64` (`x86_64-linux-android`)

### Automation Script
```bash
./scripts/build-android-jni.sh
```
Or on Windows PowerShell with Android NDK:
```powershell
.\scripts\build-android-jni.ps1 -TargetAbi all -Release
```

### Kotlin Usage (Android App)
The generated bindings live in package `uniffi.baileys_ffi` (`bindings/kotlin`).
```kotlin
import uniffi.baileys_ffi.*

class WhatsAppService : RolleysEventListener {
    private val client = RolleysClient(
        RolleysClientConfig(
            databasePath = "/data/data/com.example.app/files/rolleys_session.db",
            // Same device identity as Baileys' default (Browsers.macOS("Chrome")).
            browserName = "Chrome",
            platform = "Mac OS",
            phoneNumber = null, // set a number to pair by code instead of QR
            autoDownloadMedia = false,
        )
    )

    fun start() = client.start(this)

    override fun onEvent(event: RolleysEvent) {
        when (event) {
            is RolleysEvent.QrCode -> renderQr(event.code)
            is RolleysEvent.Connected -> onConnected(event.meJid)
            else -> {}
        }
    }

    fun sendMessage(recipientJid: String, text: String): String =
        client.sendText(recipientJid, text)
}
```

## 3. Apple Platforms (iOS & macOS Swift)

### Building XCFramework & Swift Package
```bash
./scripts/build-apple.sh --ios
```
This generates a universal fat archive and generates Swift wrappers via `uniffi-bindgen`.

### Swift Usage (iOS / macOS)
Add `bindings/swift/baileys_ffi.swift`, `baileys_ffiFFI.h` and `baileys_ffiFFI.modulemap` to your target.
```swift
final class WhatsAppManager: RolleysEventListener {
    private var client: RolleysClient?

    func initialize() throws {
        let docs = FileManager.default.urls(for: .documentDirectory, in: .userDomainMask)[0]
        let dbPath = docs.appendingPathComponent("rolleys_session.db").path

        // Same device identity as Baileys' default (Browsers.macOS("Chrome")).
        let config = RolleysClientConfig(
            databasePath: dbPath,
            browserName: "Chrome",
            platform: "Mac OS",
            phoneNumber: nil,
            autoDownloadMedia: false
        )
        let client = try RolleysClient(config: config)
        self.client = client
        try client.start(listener: self)
    }

    func onEvent(event: RolleysEvent) {
        switch event {
        case .qrCode(let code): print("QR: \(code)")
        case .connected(let meJid): print("Connected as \(meJid)")
        default: break
        }
    }
}
```

## 4. Node.js & Electron (`baileys-napi`)

Native C++ Node-API addon allowing Node.js or Bun services to run Rolleys with near-native performance:

```bash
cd bindings/baileys-napi
npm install
npm run build
```

### JavaScript / TypeScript Usage
```typescript
import { BaileysClient, SqliteStore } from 'rolleys-napi';

const store = SqliteStore.open('./session.db');
const client = new BaileysClient(store, {
    browserName: 'Chrome',
    platform: 'Mac OS',
});

client.on('qr', (qrCode) => {
    console.log('Scan QR:', qrCode);
});

client.on('message', (msg) => {
    console.log('Received message:', msg);
});

await client.connect();
await client.messages.sendText('1234567890@s.whatsapp.net', 'Hello from Node.js!');
```


## JSON message context and Android plugin exports

The Android client maintains a generated [complete UniFFI/plugin method catalog](https://github.com/Towartz/Rolleys_Android/blob/main/docs/PLUGIN_API.md)
from `bindings/kotlin/uniffi/baileys_ffi/baileys_ffi.kt`, checked against the Rust export names in
`bindings/baileys-ffi/src/lib.rs`. It lists every client export, all send methods, Kotlin argument and
return types, nullable values, and record schemas. Native callers use the ordinary typed exports;
Android JSON plugins use the typed action dispatcher. Client construction and the event listener
remain owned by the Android service.

`send_message_json(to_jid, message_json)` accepts a JSON-encoded string containing a message
shorthand or camelCase/snake_case protobuf fields. Unset protobuf fields may be omitted; repeated
fields default to empty arrays. Empty or wholly unsupported message payloads return an error,
including malformed quoted payloads. Root context is applied alongside the message payload:

```json
{
  "text": "A reply with context",
  "forwardingScore": 12,
  "mentions": ["123@s.whatsapp.net"],
  "quoted": {
    "key": {"id": "previous-message", "participant": "456@s.whatsapp.net"},
    "message": {"text": "Previous message"}
  },
  "externalAdReply": {
    "title": "Example",
    "body": "Preview description",
    "sourceUrl": "https://example.com",
    "mediaType": 1
  }
}
```

- `isForwarded` must be boolean; `forwardingScore` must be an unsigned 32-bit integer. A positive
  shorthand score sets the forwarded flag. Invalid values return a protocol error.
- `contextInfo` / `context_info` accepts protobuf ContextInfo fields. Root fields override the
  corresponding existing fields, while other nested context (such as expiration) is retained.
- Mentions, quotes, forwarding and external-ad metadata can coexist with interactive messages.
  Context is propagated into ephemeral/view-once/document-caption wrappers. Quoted JSON errors
  are surfaced instead of silently removing the quote.
- `externalAdReply.mediaType`: 0 none, 1 image, 2 video. URLs are metadata; local thumbnails/media
  are not automatically uploaded by a raw JSON descriptor. Use typed `send_image`, `send_video`,
  `send_audio`, `send_document`, `send_media_file`, etc. for encryption and upload of actual bytes.
- Raw protobuf JSON byte fields use integer arrays. The Android action bridge separately accepts
  standard base64 strings or 0..255 arrays for typed ByteArray arguments.
- Synthetic quoting/forwarding metadata does not authenticate an identity or guarantee how the
  recipient client will render the message. Success returns a message id, not a delivery receipt.

### Archive state and sync failure

`chat_modify_archive(jid, archive)` updates local chat state and emits ChatUpdate before attempting
WhatsApp app-state sync. Known phone-number/LID aliases for the conversation are kept consistent;
existing alias rows are updated without inventing additional alias conversations. Device suffixes
are removed from the input JID. A wire-sync failure is returned to the caller even though local
archive state has changed. Refresh local state after an error and retry sync when app-state keys or
connectivity are available. Passing false unarchives the same records.

### Focused regression tests

CI runs `cargo test -p baileys-core --lib messages::tests` and
`cargo test -p baileys-core --lib archive_tests`. The archive regression uses in-memory SQLite and
an unconnected client; it verifies local alias state and the event on sync failure without contacting
WhatsApp. Message tests cover combined context, omitted proto fields, validation, and wrappers.
